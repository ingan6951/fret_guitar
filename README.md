# 기타 가이드

일렉 기타 코드 운지법을 보여 주는 웹앱 (Next.js). 코드 폼 데이터는 `lib/chords.js`에 직접 적은 것만 사용합니다.

## 코드 폼 추가하기
`lib/chords.js`의 `CHORDS`에 한 줄을 추가합니다. (맨 앞 8개는 오픈 코드, 그 뒤는 프렛을 올린 바레 폼이고 맨 끝에 C·G·D 모양을 옮긴 폼이 있습니다.) `frets`는 6번 줄 → 1번 줄 순서이고, 숫자는 프렛(0=개방), `null`은 뮤트입니다.

```js
{root:4, q:'min', frets:[0,2,2,0,0,0]} // Em
```
`root`는 0=C … 11=B, `q`는 `maj`·`min`·`7`·`m7`·`maj7`·`sus4`·`sus2`·`add9`·`6`·`m6`·`7sus4`·`mmaj7`·`dim`·`dim7`·`m7b5`·`aug`·`5` (`lib/fretlogic.js`의 `QUALITIES`). 새 코드 종류는 `QUALITIES`에 구성음을 먼저 추가합니다.

## 페이지
상단 탭으로 두 페이지를 오갑니다. 상태(고른 코드·진행·고른 칸)는 같이 쓰고 브라우저에 저장됩니다. 로그인하면 다른 기기와도 같이 씁니다(아래 `기기 사이 동기화`).
- `/` 코드·지판: 근음·코드·음 개수로 코드 폼을 찾고, 아래의 **지판 음계 표**(1~6번 줄 × 0~24프렛)에서 고른 코드의 근음·구성음을 보고, 음을 누르면 같은 음이 지판 어디에 있는지 모두 밝혀 줍니다. 보기 전용입니다.
- `/progression` 진행: 진행을 만들고 고치는 일은 모두 여기서만 합니다. 이름·목록(새로 만들기·전환·삭제), 마디 차트, 고른 칸 편집, 링크 공유, 코드 폼 모아 보기.

## 진행
- 마디는 처음 4개이고 `마디 추가`로 8개까지 늘립니다.
- 마디를 고르면 그 마디에 코드가 **계속 더해집니다**(한 마디 최대 4개, 다음 마디로 자동 이동하지 않음 — 마디를 직접 고르기 전까지 같은 마디가 선택돼 있습니다). **멜로디 음**(지판 음, 최대 8개)은 따로 쌓입니다.
- 코드나 멜로디 음을 누르면 그것이 선택되고, 아래 편집 영역에서 `코드 폼`은 카드의 `↺`로 바꾸고(선택이 없으면 `+`로 마디 끝에 더함), `멜로디 음`은 지판 표에서 다른 음을 눌러 바꿉니다. `삭제`로 고른 코드·음을 지우면 뒤의 것이 앞으로 당겨지고, `마디 비우기`로 마디 전체를 비웁니다.
- 진행의 목적은 **연주할 때 기억하기 어려운 코드·멜로디를 적어 두고 보는 것**입니다. 그래서 마디 안은 `코드` 행과 `♪ 멜로디` 행으로 나뉘어 표시되고, 멜로디 음에는 **순서 번호**(1, 2, 3…)가 붙습니다. 지판 표에도 이 마디에서 그 자리가 몇 번째 음인지 번호가 나옵니다. 고른 음은 `◀ 앞으로`/`뒤로 ▶`로 순서를 바꿉니다.
- `연주용 보기`(진행 페이지 위쪽 전환): 편집 화면 없이 마디마다 코드 폼 그림과 멜로디 음(순서·음이름·몇 번 줄 몇 프렛)을 크게 보여 줍니다. 링크 복사는 여기서도 됩니다.
- 앞뒤 코드의 폼에서 손 이동이 적은 순으로 폼 카드가 정렬되고, 기준 폼(이전/다음)이 같이 보입니다.
- 진행은 여러 개(최대 20개), 이름은 최대 30자입니다. 예전에 저장된 진행(마디마다 항목 하나)은 새 형태로 옮겨 열립니다.
- 구조: `components/GuideProvider.jsx`(공통 상태·편집 동작), `Shell.jsx`(머리말·탭), `ChordFinder.jsx`·`NoteTable.jsx`(찾기/고르기 겸용), `ExplorePage.jsx`, `ProgressionPage.jsx`, 마디 데이터와 링크 변환은 `lib/settings.js`.

## 곡 빠르기·메트로놈
- 진행 하나가 곡 하나입니다. 곡마다 빠르기(`bpm`, 30~250)와 박자(`beats`, 2~7 → n/4)를 저장합니다(기본 90 BPM, 4/4).
- 진행 페이지의 메트로놈 줄: `▶ 메트로놈`/`■ 정지`, `−`/`+`·직접 입력·`탭`(박자에 맞춰 누르기)으로 빠르기, 박자 선택. 재생 중에는 지금 박과 연주 중인 마디(마지막으로 무언가 적힌 마디까지 반복)가 강조됩니다.
- 엔진은 `lib/metronome.js`(Web Audio에 클릭을 미리 예약). `start({startAt})`은 정해진 오디오 시각을 0번째 박으로 삼고, 이미 지났으면 같은 박자 격자의 다음 박부터 냅니다. `lead`는 이어폰 지연 보정값입니다. 둘 다 합주(방장과 같이 시작) 기능에서 씁니다.

## 합주 방 (`/room/?id=...`)
같은 곡을 각자 이어폰으로 들으며 박자를 맞추기 위한 방입니다. 서버는 Supabase Realtime(Broadcast·Presence)만 쓰고 데이터베이스 테이블은 없습니다.
- 진행 페이지의 `🎧 합주 방 만들기` → 이 기기가 방장(브라우저에 기억)이 되고, 방장 화면은 지금 곡의 빠르기·박자를 씁니다. `방 링크 복사`로 링크를 나눕니다.
- 참여자는 링크로 들어와 `소리 켜고 참여`(모바일 소리 정책 때문에 한 번 눌러야 함). 방장이 재생하면 모두 같은 박에 울리고, 늦게 들어와도 다음 박부터 맞춥니다. 재생 중 빠르기를 바꾸면 0.7초 뒤의 박부터 다 같이 바뀝니다.
- 동기화: 참여자가 방장에게 ping을 보내 시계 차이를 잽니다(`lib/sync.js`, 왕복이 짧은 샘플의 중앙값, 30초마다 다시). 방장은 "방장 시계로 이 시각에 0번째 박" 격자를 보내고, 각 기기는 그 시각을 자기 시계로 바꿔 `lib/metronome.js`가 예약합니다. 메트로놈은 박마다 오디오 출력 타임스탬프로 변환해 브라우저가 아는 출력 지연까지 반영합니다. 같은 컴퓨터의 두 브라우저로 잰 박 차이는 약 2ms였습니다.
- 듣는 기기 맞추기: 방에 들어오면(방장·참여자 모두) 먼저 `무엇으로 들으세요?`를 묻습니다. `휴대폰 스피커·유선 이어폰`은 0ms로 바로 참여, `블루투스 이어폰`은 들리는 클릭(100BPM)에 맞춰 8번 눌러 지연을 잽니다(`lib/sync.js`의 `leadFromTaps`: -150~450ms 범위, 처음 두 번 제외 중앙값, 고르지 않으면 다시 재라고 안내). 재는 동안에는 박을 화면에 보여 주지 않습니다. 고른 기기와 값은 기기에 저장(`fretguide.output`, `fretguide.lead`)되어 다음엔 묻지 않고, 아래 `지연 보정` 메뉴에서 슬라이더·다시 재기·`듣는 기기 다시 고르기`를 할 수 있습니다.
- 설정: `.env.local`에 `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY`(publishable key). 정적 빌드에 박히므로 배포 환경(Vercel 등)의 환경 변수에도 같은 값을 넣어야 합니다. 값이 없으면 방 만들기 버튼이 숨겨집니다.
- 연결 코드는 `lib/room.js` 하나뿐이고(클라이언트는 로그인과 같이 쓰는 `lib/supabase.js`), 테스트는 `tests/shims/supabase.js`(메모리 버스)로 대신합니다.
- 한계: 방 id를 아는 사람은 누구나 방장 메시지를 흉내 낼 수 있습니다(공개 채널). 방 id는 추측하기 어려운 10글자입니다.

## 기기 사이 동기화 (로그인)
⚙ 보기 설정 안의 `다른 기기와 같이 쓰기`에서 이메일로 로그인하면, 진행 목록과 코드 조건·표시 설정을 다른 기기에서도 그대로 봅니다(Supabase Auth + `user_settings` 테이블).
- 로그인: 이메일을 넣으면 메일이 옵니다. 메일의 링크를 누르거나, 메일에 있는 숫자 코드를 앱에 넣습니다(메일 앱 안 브라우저에서 링크가 열려 로그인이 엉뚱한 곳에 될 때 코드가 편합니다).
- 흐름(`components/useCloudSync.js`, 판단은 `lib/cloud.js`의 `decide`): 로그인하면 먼저 서버 값을 읽습니다. 이 기기가 비어 있거나 안 바뀌었으면 서버 것을 받고, 서버에 없으면 이 기기 것을 올립니다. 둘 다 서로 모르는 변경이 있으면 서버 진행 뒤에 이 기기에만 있는 진행을 붙여 둘 다 남깁니다. 그다음부터는 바꾼 뒤 1.2초 지나면 올리고, 탭으로 돌아올 때마다 다시 읽습니다.
- 지금 고른 진행(`cur`)과 합주 방 관련 값(듣는 기기·지연·방장 기록)은 기기마다 따로입니다. 로그아웃해도 이 기기에 저장된 내용은 남습니다.
- 서버 준비(한 번):
  1. Supabase 대시보드 → SQL Editor에서 `supabase/user_settings.sql` 실행(테이블 + 자기 줄만 읽고 쓰는 RLS 정책).
  2. Authentication → Sign In / Providers에서 Email 켜기.
  3. Authentication → URL Configuration: `Site URL`에 배포 주소, `Redirect URLs`에 `https://배포주소/**`와 `http://localhost:3000/**`.
  4. (코드로 로그인하려면) Authentication → Emails → `Magic Link` 템플릿에 `{{ .Token }}`을 넣기. 기본 메일 발송은 시간당 몇 통으로 제한되므로, 여러 사람이 쓰면 SMTP를 따로 설정합니다.
- 서버 설정(`NEXT_PUBLIC_SUPABASE_*`)이 없으면 로그인 칸이 보이지 않습니다. 테스트는 `tests/shims/supabase.js`의 가짜 auth·테이블로 대신합니다.

## 진행 공유
`/progression` 의 `링크 복사`로 `/progression/?p=...&t=제목&bpm=96&ts=4` 링크를 만들고, 다른 기기·브라우저에서 열면 같은 진행이 **새 진행으로 추가**됩니다(기존 진행은 그대로, 서버 저장 없음). 링크의 `p`는 마디를 `~`로, 마디 안은 `코드,코드|음,음`으로 적습니다(코드는 `근음-종류-프렛들`, 음은 `줄.프렛`, 빈 마디 `_`). 예전 형식의 링크도 읽습니다.
